## 1. Основной Пайплайн Выполнения Задачи

**Описание:** Это главный пайплайн, который управляет всем жизненным циклом выполнения задачи от начала до конца.

**Входные данные:**
- Задача пользователя (task)
- Изображения (images, optional)
- История (historyItem, optional)

**Выходные данные:**
- Результат выполнения задачи
- История сообщений
- Использование токенов и инструментов

**ASCII Схема:**

```
┌─────────────────────────────────────────────────────────────────┐
│                    НАЧАЛО ЗАДАЧИ                                 │
│                 (User submits task)                              │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│              ИНИЦИАЛИЗАЦИЯ CLINE INSTANCE                        │
│  - Создание taskId, instanceId                                  │
│  - Загрузка конфигурации API                                     │
│  - Инициализация fileContextTracker                              │
│  - Инициализация browserSession                                  │
│  - Загрузка customInstructions                                   │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│              ГЕНЕРАЦИЯ СИСТЕМНОГО ПРОМТА                         │

│  - Добавление изображений (если есть)                            │

└────────────────────────┬────────────────────────────────────────┘
                         │

┌─────────────────────────────────────────────────────────────────┐
│              ОСНОВНОЙ ЦИКЛ ЗАДАЧИ                                │

│  │                │                         │                    │
│  │                ▼                         │                    │

│  │    │ Обработка ответа LLM:            │ │                    │

│  │                │                         │                    │
│  │                ▼                         │                    │
│  │    ┌──────────────────────────────────┐ │                    │
│  │    │ Есть tool_use?                   │ │                    │
│  │    └───────────┬──────────────────────┘ │                    │
│  │           ┌────┴────┐                    │                    │
│  │          ДА         НЕТ                  │                    │
│  │           │          │                   │                    │
│  │           ▼          ▼                   │                    │
│  │    ┌──────────┐  ┌─────────────────┐    │                    │
│  │    │ Execute  │  │ Подсказка:      │    │                    │
│  │    │ Tool     │  │ "Завершить или  │    │                    │
│  │    │          │  │  продолжить?"   │    │                    │
│  │    │См. Tool  │  │consecutiveMis-  │    │                    │
│  │    │Pipeline  │  │take++           │    │                    │
│  │    └──────────┘  └─────────────────┘    │                    │
│  │           │          │                   │                    │

│  │    └──────────────────────────────────┘ │                    │
│  │                                          │                    │
│  └──────────────────────────────────────────┘                    │

                         ▼

│  - Максимум запросов достигнут                                   │
│  - Пользователь прервал                                          │
│  - Сохранение истории                                            │
│  - Emit taskCompleted event                                      │
└─────────────────────────────────────────────────────────────────┘
```

**Поток данных между итерациями:**

```
Итерация N:
  Input:  UserContent (задача или tool_result)
  LLM:    System Prompt + History + UserContent → Response
  Output: AssistantMessage (text + tool_use blocks)
          ↓
  Validation: validateToolUse (проверка ограничений режима)
          ↓
  Execution: executeTool → ToolResult
          ↓
Итерация N+1:
  Input:  UserContent (tool_result от предыдущей итерации)
  ...
```

**Ключевые компоненты:**
- `Cline.ts` - главный класс агента
- `initiateTaskLoop()` - запуск основного цикла
- `recursivelyMakeClineRequests()` - рекурсивные запросы к LLM
- `apiConversationHistory` - история всех сообщений
- `clineMessages` - сообщения для UI

## 2. Пайплайн Генерации Системного Промта

**Описание:** Процесс сборки полного системного промта из различных секций.

**Входные данные:**
- Режим работы (mode)
- Рабочая директория (cwd)
- Конфигурация (diffStrategy, mcpHub, customInstructions и т.д.)

**Выходные данные:**
- Полный текст системного промта

**ASCII Схема:**

```
┌─────────────────────────────────────────────────────────────────┐
│              SYSTEM_PROMPT() вызов                               │
│  src/core/prompts/system.ts                                      │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│    Проверка наличия кастомного системного промта                │
│    loadSystemPromptFile(cwd, mode, variables)                   │
│                                                                  │
│    Поиск файла: .roo/system-prompt-{mode_slug}                  │
└────────────────────────┬────────────────────────────────────────┘
                    ┌────┴────┐
              НАЙДЕН         НЕ НАЙДЕН
                    │          │
                    ▼          ▼
         ┌────────────────┐  ┌──────────────────────────────────┐
         │ Использовать   │  │ Генерация стандартного промта    │
         │ кастомный      │  │ generatePrompt()                 │
         │ промт          │  └──────────┬───────────────────────┘
         └────────────────┘             │
                                        ▼
                    ┌──────────────────────────────────────────────┐
                    │  Параллельная загрузка секций:               │
                    │  ┌────────────────────────────────────────┐  │
                    │  │ 1. getModesSection(context)            │  │
                    │  │    Загружает доступные режимы          │  │
                    │  └────────────────────────────────────────┘  │
                    │  ┌────────────────────────────────────────┐  │
                    │  │ 2. getMcpServersSection()              │  │
                    │  │    (если режим поддерживает MCP)       │  │
                    │  │    Загружает информацию о MCP серверах │  │
                    │  └────────────────────────────────────────┘  │
                    └──────────────────────────────────────────────┘
                                        │
                                        ▼
                    ┌──────────────────────────────────────────────┐
                    │  Последовательная сборка промта:             │
                    │                                              │
                    │  1. roleDefinition                           │
                    │     "You are Roo, a highly skilled..."       │
                    │                                              │
                    │  2. getSharedToolUseSection()                │
                    │     Базовые правила работы с инструментами   │
                    │                                              │
                    │  3. getToolDescriptionsForMode()             │
                    │     Список инструментов для режима           │
                    │                                              │
                    │  4. getToolUseGuidelinesSection()            │
                    │     Руководство по использованию             │
                    │                                              │
                    │  5. mcpServersSection                        │
                    │     Информация о MCP (если есть)             │
                    │                                              │
                    │  6. getCapabilitiesSection()                 │
                    │     Возможности агента                       │
                    │                                              │
                    │  7. modesSection                             │
                    │     Доступные режимы                         │
                    │                                              │
                    │  8. getRulesSection()                        │
                    │     Правила работы                           │
                    │                                              │
                    │  9. getSystemInfoSection()                   │
                    │     Системная информация                     │
                    │                                              │
                    │  10. getObjectiveSection()                   │
                    │      Цели и задачи                           │
                    │                                              │
                    │  11. addCustomInstructions()                 │
                    │      Пользовательские инструкции             │
                    └──────────────────────────────────────────────┘
                                        │
                                        ▼
                    ┌──────────────────────────────────────────────┐
                    │  Возврат полного системного промта           │
                    └──────────────────────────────────────────────┘
```

**Поток данных в addCustomInstructions():**

```
addCustomInstructions(modeCustomInstructions, globalCustomInstructions, cwd, mode, options)
                    │
                    ├─> Language Preference (если задан options.language)
                    │   "You should always speak in {language}"
                    │
                    ├─> Global Instructions
                    │   Из настроек пользователя
                    │
                    ├─> Mode-specific Instructions
                    │   Из конфигурации режима
                    │
                    └─> Rules
                        │
                        ├─> Mode-specific rules
                        │   .pearai-agent/rules-{mode}/ (все файлы)
                        │   или .roorules-{mode}
                        │   или .clinerules-{mode}
                        │
                        └─> Generic rules
                            .pearai-agent/rules/ (все файлы)
                            или .roorules
                            или .clinerules
                            
                    ↓
        Объединение всех секций с заголовком:
        "==== USER'S CUSTOM INSTRUCTIONS"
```

**Ключевые особенности:**
- Модульная структура позволяет легко добавлять новые секции
- Поддержка кастомных промтов через файлы `.roo/system-prompt-{mode}`
- Динамическая генерация на основе конфигурации
- Кэширование промтов для оптимизации

## 3. Пайплайн Обработки Инструментов

**Описание:** Процесс выполнения инструментов (tools) от парсинга до получения результата.

**Входные данные:**
- Ответ LLM с блоками tool_use
- Текущее состояние задачи
- Контекст выполнения

**Выходные данные:**
- Результаты выполнения инструментов (tool_result)
- Обновленное состояние задачи

**ASCII Схема:**

```
┌─────────────────────────────────────────────────────────────────┐
│          LLM Response с tool_use блоками                         │
│  [                                                               │
│    { type: "thinking", thinking: "..." },                       │
│    { type: "tool_use", name: "read_file", input: {...} }        │
│  ]                                                               │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│          parseAssistantMessage()                                 │
│  Парсинг ответа LLM в структурированный формат                   │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│    Для каждого tool_use блока:                                   │
│                                                                  │
│    ┌──────────────────────────────────────────────────────────┐ │
│    │ 1. Валидация инструмента                                 │ │
│    │    validateToolUse(toolName, mode)                       │ │
│    │                                                          │ │
│    │    Проверка:                                             │ │
│    │    - Разрешен ли инструмент для текущего режима?        │ │
│    │    - Соответствует ли использование ограничениям?       │ │
│    └──────────────────┬───────────────────────────────────────┘ │
│                       │                                          │
│                  ┌────┴────┐                                     │
│             ВАЛИДЕН    НЕ ВАЛИДЕН                                │
│                  │         │                                     │
│                  │         └──> FileRestrictionError             │
│                  │                     ↓                         │
│                  │              Возврат ошибки пользователю      │
│                  │                                               │
│                  ▼                                               │
│    ┌──────────────────────────────────────────────────────────┐ │
│    │ 2. Отображение инструмента в UI                          │ │
│    │    presentAssistantMessage()                             │ │
│    │    - Показать thinking                                   │ │
│    │    - Показать использование инструмента                  │ │
│    │    - Статус: "loading"                                   │ │
│    └──────────────────┬───────────────────────────────────────┘ │
│                       │                                          │
│                       ▼                                          │
│    ┌──────────────────────────────────────────────────────────┐ │
│    │ 3. Запрос подтверждения у пользователя                  │ │
│    │    (если autoApprove отключен)                           │ │
│    │                                                          │ │
│    │    askApproval(tool, params)                             │ │
│    └──────────────────┬───────────────────────────────────────┘ │
│                  ┌────┴────┐                                     │
│            ОДОБРЕНО    ОТКЛОНЕНО                                 │
│                  │         │                                     │
│                  │         └──> Возврат "Tool rejected"          │
│                  │                     ↓                         │
│                  │              didRejectTool = true             │
│                  │                                               │
│                  ▼                                               │
│    ┌──────────────────────────────────────────────────────────┐ │
│    │ 4. Выполнение инструмента                                │ │
│    │    executeTool(toolName, toolInput)                      │ │
│    │                                                          │ │
│    │    Маршрутизация к конкретному инструменту:             │ │
│    │    ┌──────────────────────────────────────────────────┐ │ │
│    │    │ switch (toolName) {                              │ │ │
│    │    │   case "read_file":                              │ │ │
│    │    │     return readFileTool.execute(...)             │ │ │
│    │    │   case "write_to_file":                          │ │ │
│    │    │     return writeToFileTool.execute(...)          │ │ │
│    │    │   case "execute_command":                        │ │ │
│    │    │     return executeCommandTool.execute(...)       │ │ │
│    │    │   case "attempt_completion":                     │ │ │
│    │    │     return attemptCompletionTool.execute(...)    │ │ │
│    │    │   // ... другие инструменты                      │ │ │
│    │    │ }                                                │ │ │
│    │    └──────────────────────────────────────────────────┘ │ │
│    └──────────────────┬───────────────────────────────────────┘ │
│                       │                                          │
│                       ▼                                          │
│    ┌──────────────────────────────────────────────────────────┐ │
│    │ 5. Обработка результата                                  │ │
│    │                                                          │ │
│    │    ToolResponse:                                         │ │
│    │    - toolResult (для отправки в LLM)                    │ │
│    │    - userMessage (для отображения пользователю)         │ │
│    │    - didContinue (продолжить ли выполнение)             │ │
│    │    - isError (произошла ли ошибка)                      │ │
│    └──────────────────┬───────────────────────────────────────┘ │
│                       │                                          │
│                       ▼                                          │
│    ┌──────────────────────────────────────────────────────────┐ │
│    │ 6. Обновление UI                                         │ │
│    │    - Статус: "approved" / "rejected" / "error"          │ │
│    │    - Отображение результата                              │ │
│    │    - Обновление истории сообщений                        │ │
│    └──────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│    Формирование tool_result для следующего запроса к LLM        │
│                                                                  │
│    {                                                             │
│      type: "tool_result",                                        │
│      tool_use_id: "...",                                         │
│      content: [результат выполнения]                             │
│    }                                                             │
└─────────────────────────────────────────────────────────────────┘
```

**Специфические пайплайны инструментов:**

### 3.1 read_file Pipeline

```
readFileTool.execute(path, start_line, end_line)
    │
    ├─> Валидация пути (относительно cwd)
    │
    ├─> Чтение файла
    │   - Если PDF/DOCX: извлечение текста
    │   - Если start_line/end_line: стриминг диапазона
    │   - Иначе: полное чтение
    │
    ├─> Добавление номеров строк
    │   "1 | const x = 1"
    │   "2 | const y = 2"
    │
    └─> Возврат результата
        - toolResult: содержимое файла с номерами строк
        - userMessage: подтверждение чтения
```

### 3.2 write_to_file Pipeline

```
writeToFileTool.execute(path, content, line_count)
    │
    ├─> Валидация:
    │   - Проверка полноты контента
    │   - Проверка line_count
    │
    ├─> Показ diff preview (если diffEnabled)
    │   DiffViewProvider.showDiff(oldContent, newContent)
    │   ┌────────────────────────────────┐
    │   │ ┌─────────┐   ┌─────────┐     │
    │   │ │  OLD    │   │   NEW   │     │
    │   │ │ Content │ → │ Content │     │
    │   │ └─────────┘   └─────────┘     │
    │   │                                │
    │   │ Пользователь видит изменения  │
    │   └────────────────────────────────┘
    │
    ├─> Запрос подтверждения (если autoApprove=false)
    │
    ├─> Создание резервной копии
    │   (для возможности отката)
    │
    ├─> Запись файла
    │   - Создание директорий (если нужно)
    │   - Запись контента
    │
    ├─> Обновление fileContextTracker
    │   (отслеживание измененных файлов)
    │
    └─> Возврат результата
        - toolResult: "Successfully wrote to {path}"
        - userMessage: diff preview + confirmation
```

### 3.3 execute_command Pipeline

```
executeCommandTool.execute(command, cwd)
    │
    ├─> Создание нового терминала
    │   TerminalRegistry.getOrCreateTerminal(taskId)
    │
    ├─> Показ команды пользователю
    │
    ├─> Запрос подтверждения
    │
    ├─> Выполнение команды в терминале
    │   Terminal.runCommand(command, cwd)
    │   ┌────────────────────────────────┐
    │   │  VSCode Terminal               │
    │   │  $ command                     │
    │   │  [output streams...]           │
    │   └────────────────────────────────┘
    │
    ├─> Сбор вывода
    │   - stdout
    │   - stderr  
    │   - exit code
    │
    ├─> Обработка фоновых процессов
    │   (если команда long-running)
    │
    └─> Возврат результата
        - toolResult: вывод команды
        - userMessage: статус выполнения
```

### 3.4 attempt_completion Pipeline

```
attemptCompletionTool.execute(result, command)
    │
    ├─> Проверка: все ли предыдущие инструменты успешны?
    │   - Если нет: ошибка "Cannot complete without confirmation"
    │
    ├─> Отображение результата пользователю
    │   presentAssistantMessage(result)
    │
    ├─> Выполнение демо команды (если указана)
    │   execute_command(command)
    │   Например: open index.html
    │

    │   - didContinue = true

    └─> Если принято:
```
